CHAPTER 02

LTEネットワークの全体像

ロボットのLTEモジュールから出た電波は、基地局・コア網を経てインターネットや社内サーバに届きます。途中にいる「登場人物」と、その役割分担を地図のように頭に入れましょう。

この章のゴール

  • UE・eNodeB・MME・S-GW・P-GW・HSS・PCRF がそれぞれ何をしているか説明できる
  • 「データの通り道（ユーザープレーン）」と「制御の通り道（コントロールプレーン）」の違いがわかる
  • ロボットが移動したときのセル切り替え（ハンドオーバー）の流れがわかる
  • APN・IPアドレス・CGNATの関係と、ロボットを遠隔操作・監視するための接続方式を選べる
  • MNOとMVNOの違い、5G（NSA/SA）とLTEの関係を大まかに説明できる

1. 登場人物を「物流網」にたとえる

LTEのネットワークは大きく3つのブロックに分かれます。端末（UE：User Equipment）、基地局の集まりである無線アクセス網（E-UTRAN：Evolved Universal Terrestrial Radio Access Network）、そして携帯事業者の建物の中にあるコア網（EPC：Evolved Packet Core）です。EPCの先に、インターネットや企業のネットワークがつながっています。

いきなり略語が並ぶと覚えにくいので、宅配便の物流網にたとえてみます。

LTEの要素物流網でいうとひとことで
UE（端末）荷物を出す・受け取るお客さんロボットに載ったLTEモジュール＋SIM
eNodeB（基地局）近所の営業所電波で端末と直接やり取りする窓口
MME受付・配車センター（司令塔）本人確認、居場所の管理、通り道の手配
HSS会員名簿契約情報と認証の元データ
S-GW地域の集配センター基地局からのデータを束ねて中継
P-GW外部への出入口（ゲート）IPアドレスを配り、インターネット等へ出す
PCRF料金表・ルール係速度制限や課金ルールを決める

ポイントは、「荷物（データ）を運ぶ係」と「段取り（制御）をする係」が分かれていることです。MMEやHSSは荷物に触れず、手配だけをします。S-GWやP-GWは手配どおりに荷物を運びます。この分業が次の節の主役です。

用語の整理：EPS = E-UTRAN + EPC

無線部分（E-UTRAN）とコア網（EPC）を合わせたLTEのシステム全体をEPS（Evolved Packet System）と呼びます。「LTE」は本来は無線方式の名前ですが、日常的にはシステム全体を指して使われます。

3. ユーザープレーンとコントロールプレーン

図のボタンで経路を切り替えると、2種類の流れがまったく違う道を通っていることがわかります。

  • ユーザープレーン（U-plane）：ロボットのセンサー値、カメラ映像、クラウドからの指令など、アプリが送りたい中身が通る道。UE → eNodeB → S-GW → P-GW → 外部。
  • コントロールプレーン（C-plane）：接続の申し込み、認証、居場所の報告、「通り道を作って／消して」といった段取りの会話が通る道。UE ⇄ eNodeB ⇄ MME ⇄ HSS／S-GW など。

電話で言えば、C-planeは「呼び出し音を鳴らして相手を探し、回線をつなぐ交換手」、U-planeは「つながった後の会話そのもの」です。分けておくことで、データ量が増えたらS-GW／P-GWだけを増強し、端末数が増えたらMMEを増強する、というように独立して設計・拡張できます。

ユーザーデータは、S-GWやP-GWの間ではGTP-U（GPRS Tunnelling Protocol for User Plane）という「トンネル」に包まれて運ばれます。ロボットのIPパケットをそのまま別の封筒に入れて運ぶイメージで、この封筒の単位（端末とP-GWをつなぐ論理的な通り道）をベアラ（EPS Bearer）と呼びます。LTEでは接続（アタッチ）した時点で既定の通り道＝デフォルトベアラが作られるため、電源を入れて登録が済めば、すぐにIP通信ができる「常時接続」になります。

インターフェースつなぐもの種類運ぶもの
LTE-UuUE ⇄ eNodeB無線データと制御の両方
S1-MMEeNodeB ⇄ MME制御接続・認証・ハンドオーバーの指示（S1AP）、端末とMMEの会話（NAS）
S1-UeNodeB ⇄ S-GWデータユーザーデータ（GTP-U）
S11MME ⇄ S-GW制御ベアラの作成・変更（GTP-C）
S6aMME ⇄ HSS制御認証データ・契約情報（Diameter）
S5 / S8S-GW ⇄ P-GW両方ユーザーデータ＋ベアラ制御。S8は他社網（ローミング）をまたぐ場合
GxPCRF ⇄ P-GW制御QoS・課金ルール
SGiP-GW ⇄ 外部網データ普通のIPパケット（ここからは一般のネットワーク）

私たちのロボットにとっての意味

開発者が直接触るのは、ほぼUE（モジュール）とP-GWの先（クラウドや社内サーバ）だけです。とはいえ「つながらない」ときにモジュールが返すエラー（認証失敗、APN拒否など）は、MMEやHSS、P-GWとの会話の結果です。どの装置で止まっているかを想像できると、原因切り分けが格段に速くなります（第3章のトラブルシュート図を参照）。

4. セルとハンドオーバー：走るロボットはどう乗り換える？

1つの基地局の電波が届く範囲をセルと呼びます。実際には1つの基地局が複数の方向・周波数にアンテナを持ち、複数のセルを作っています。セルの大きさは周波数や設置場所で大きく変わり、都市部では数百m、郊外では数km以上になることもあります。隣り合うセルは少しずつ重なるように配置され、端末はその重なりの中で乗り換えます。

乗り換えには2種類あります。

  • 待ち受け中（RRC Idle）：端末が自分で電波の強いセルを選び直します（セル再選択）。ネットワークには細かく報告せず、複数のセルをまとめたトラッキングエリア（TA）をまたいだときだけ位置登録（TAU：Tracking Area Update）を行います。
  • 通信中（RRC Connected）：ネットワークが主導して乗り換えさせます。これがハンドオーバーです。下のステップで流れを見てみましょう。
移動ロボットで気をつけること
  • セル境界での品質低下：境目では電波が弱く干渉も多いため、速度が落ちたり遅延が増えたりします。遠隔操縦の映像はビットレートを動的に下げられる設計にしましょう。
  • 電波の「穴」：エレベーター、地下、金属棚の多い倉庫などでは圏外になり得ます。ハンドオーバーでは救えないので、再接続とデータの再送（キューイング）をアプリ側で必ず用意します。
  • アンテナの配置：ロボットの金属筐体の内側にアンテナを置くと、セル端での受信が一気に悪化します（第6章）。

5. APN・IPアドレス・CGNAT：ロボットに「外から」つなげたいとき

APN：どの出口から出るかの「行き先指定」

APN（Access Point Name）は、端末が接続時に「どのネットワークにつなぎたいか」を示す名前です。例えば internet.example のような文字列で、コア網はAPNを見て使うP-GW（出口）と、そこから先の接続先（インターネットか、ある企業の閉域網か）を決めます。SIMの契約で使えるAPNはHSSに登録されており、APNの設定が間違っていると、電波はつかんでいてもデータ通信ができません。これは「つながらない」原因の代表格です。

APNごとにP-GWがIPアドレスを割り当てます。IPv4、IPv6、あるいは両方（IPv4v6）が選べる回線もあります。ここで問題になるのが、そのIPアドレスの「種類」です。

CGNAT：多くの回線で端末はNATの内側にいる

IPv4アドレスは世界的に枯渇しているため、多くのモバイル回線では端末にプライベートIPアドレス（10.x.x.x など）や、キャリア用に予約された共有アドレス（100.64.0.0/10、RFC 6598）を割り当て、出口でCGNAT（Carrier-Grade NAT：キャリアグレードNAT）によって少数のグローバルIPに変換しています。マンションの各部屋に内線番号だけがあり、外線は代表番号1本しかない状態を想像してください。

  • ロボットから外へ電話をかける（アウトバウンド接続）→ 代表番号から発信され、折り返しも正しい部屋に戻ってくる。できる。
  • 外からロボットへ電話をかける（インバウンド接続）→ 代表番号にかけても、どの部屋か指定できない。できない。

遠隔からロボットにアクセスする方法の比較

「ロボットの状態をいつでも見たい」「現場に行かずにログを取りたい・設定を変えたい」という要望はほぼ必ず出てきます。代表的な方法を比較します。

方式仕組み良い点注意点
MQTT等のアウトバウンド常時接続ロボットからクラウドのブローカー（AWS IoT Core、Azure IoT Hub、自前のMQTTサーバ等）へTLSで接続し続けるどの国・どの回線でも動く。回線の種類に依存しない。通信量が小さいキープアライブ設計が必要。SSHのような「直接ログイン」ではない（コマンドをメッセージとして送る）
端末からのVPNロボットがWireGuard・IPsec・OpenVPNなどで自社のVPNサーバに接続し、社内網の一員になるSSHやWeb管理画面など既存の手段がそのまま使えるVPNサーバの運用が必要。暗号化のオーバーヘッドで通信量がやや増える
閉域網（閉域APN）キャリア／MVNOの閉域サービスで、P-GWの先を専用線・VPNで自社網へ直結インターネットに出ないので安全。端末のIPを固定・指定できることが多い国ごと・事業者ごとの契約になり、海外展開では同じ仕組みを揃えにくい。費用が高め
グローバル固定IPオプション契約で端末にインターネットから到達可能な固定IPを付与仕組みが単純。外から直接アクセスできるインターネットから攻撃される入口にもなる。提供している事業者・国が限られる

おすすめの基本設計

輸出先の国ごとに回線事業者が変わる可能性が高いので、「ロボットからクラウドへTLSのアウトバウンド接続（MQTTなど）」を標準にし、回線の種類に依存しない設計にするのが安全です。保守用のシェルアクセスが必要なら、その上に必要なときだけ張るVPNや事業者のリモートアクセス機能を追加します。固定グローバルIPで常時ポートを開けるのは、セキュリティ上おすすめしません。

IPv6なら直接届く？

IPv6ではNATなしでグローバルアドレスが割り当てられる回線もあります。ただし多くの事業者は外部からの着信をファイアウォールで遮断しており、また全ての国・回線でIPv6が使えるとは限りません。「IPv6なら外から届くはず」と前提にせず、実回線で確認してください。

6. MNOとMVNO：回線は誰から買う？

MNO（Mobile Network Operator：移動体通信事業者）は、国から周波数の免許を受け、自前で基地局とコア網を持つ事業者です。日本ならNTTドコモ、KDDI（au）、ソフトバンク、楽天モバイルがこれにあたります。

MVNO（Mobile Virtual Network Operator：仮想移動体通信事業者）は、MNOの無線網を借りてサービスを提供する事業者です。「どこまで自前の設備を持つか」によって、できることが変わります。

設備MNOライトMVNO
（日本のL2接続型など）		フルMVNO
周波数免許・基地局（E-UTRAN）自前借りる借りる
MME・S-GW自前借りる借りる
P-GW相当（出口・IP割当）自前自前自前
HSS（加入者管理）・SIM発行自前借りる自前
料金・顧客管理自前自前自前

出口（P-GW相当）を自前で持つMVNOは、閉域網接続やIoT向けの独自機能（管理画面からのSIMの停止・再開、通信量の監視など）を提供しやすくなります。HSSまで自前で持つフルMVNOは、自社の加入者番号（IMSI）でSIMを発行できるため、「出荷前は課金しない」「現地の回線に切り替える」といった柔軟な運用が可能になります（日本ではIIJが2018年にフルMVNOとしてのサービスを開始）。

海外展開で重要なのがローミングです。ロボットが日本のSIMのまま海外で通信するとき、現地のMNOの基地局とS-GWを使い、S8インターフェースで日本側（ホーム網）のP-GWへ戻る方式（ホームルーティング）が一般的です。IPアドレスや閉域網の設定は日本と同じまま使える一方、通信経路が長くなり遅延が増えます。現地回線とローミングのどちらを選ぶか、各国の規制（恒久的なローミングを制限する国もあります）は第7章・第10章で扱います。

IoT向け回線を選ぶ観点

ロボット用途では、スマホ向けの料金プランよりも、IoT向けのMVNO・MNOプランが向いていることが多いです。①複数国で使えるか（グローバルSIM）、②閉域網・VPN・リモートアクセスの機能、③SIMの一括管理（API・管理画面）、④低容量プランや休止状態の料金、⑤対応するLTEカテゴリ（LTE-M／NB-IoTに対応しているか）を比較しましょう。

7. 5Gとの関係：NSAとSA

5Gの導入方式には2つあります。

  • NSA（Non-Standalone）：LTEの基地局とEPCを土台として、5Gの無線（NR：New Radio）を速度の上乗せとして追加する方式です（EN-DC：E-UTRA–NR Dual Connectivity）。接続や制御はLTE側が担うため、LTEの電波が前提です。
  • SA（Standalone）：5G専用のコア網5GC（5G Core）で独立して動く方式です。ネットワークスライシングや低遅延など5G本来の機能はSAで実現されます。

5GCはEPCの役割を分割・再編した構成になっています。大まかな対応関係は次のとおりです。

ロボットはLTEで大丈夫？

IoT向けのLTE（Cat-1、LTE-M、NB-IoTなど）は、5G時代にも継続して使われることを前提に3GPPで位置付けられています（LTE-MとNB-IoTは5Gの要件を満たす技術として扱われています）。また、各国で4Gの網は5Gの土台として当面運用が続く見込みです。ただし2G/3Gのように、将来LTEが縮小する国が出る可能性はあるので、製品寿命（10年以上？）と各国の動向は定期的に確認しましょう。カテゴリの選び方は第5章で比較します。

まとめ

  • LTEは UE → eNodeB（E-UTRAN）→ EPC → 外部網 の構成。EPCの主要装置は MME・HSS・S-GW・P-GW・PCRF。
  • データ（U-plane）は eNodeB → S-GW → P-GW を、制御（C-plane）は eNodeB → MME ⇄ HSS／S-GW を通る。MMEはデータを運ばない。
  • 通信中のセル移動は基地局主導のハンドオーバー。P-GWが固定点なのでIPアドレスは変わらず、セッションも維持される。
  • APNで出口（P-GW）と接続先が決まる。多くの回線はCGNAT配下で外から届かない。遠隔アクセスはアウトバウンド接続（MQTT等）を基本に、VPN・閉域網を組み合わせる。
  • MNOは免許と網を持つ事業者、MVNOは網を借りる事業者。どこまで自前か（出口・HSS）で機能が変わる。
  • 5G NSAはLTE＋EPCが土台、SAは5GCで独立。
