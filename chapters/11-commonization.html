CHAPTER 11

国ごとの部品共通化戦略

アジア各国へ輸出するとき、ロボットを国の数だけ作り分けるのは大変です。どの部品は世界共通にでき、どこは国ごとに変えざるを得ないのか。「1機種で何か国まで行けるか」を考えるための道具をそろえます。

この章のゴール

  • ロボットの構成要素を「共通化しやすい／条件付き／国別になりがち」に分けて説明できる
  • 通信部の4つの戦略（グローバル1SKU・地域版＋共通基板・通信カード差し替え・外付けゲートウェイ）の長所短所を比べられる
  • アンテナの広帯域化、認証の再利用、eSIM、国別設定の考え方を理解する
  • 台数や認証費から、どの戦略が有利かを概算できる

1. なぜ「共通化」が大事なのか

製品の世界では、在庫や生産を管理する単位を SKU（Stock Keeping Unit：在庫管理単位）と呼びます。「日本向けロボット」と「タイ向けロボット」で中身が1つでも違えば、SKUは2つです。SKUが1つ増えるたびに、次のような仕事がまるごと増えます。

  • 設計・検証：部品表（BOM：Bill of Materials）が別になり、試験も別に回す
  • 認証：電波認証やキャリア認証を型番ごとに取り直す可能性がある
  • 調達・在庫：部品ごとに発注量が分散して単価が下がりにくく、売れ残りのリスクも国ごとに発生
  • 生産：ラインの段取り替え、ラベル・梱包の取り違え防止
  • 保守：修理部品、ファームウェア、問い合わせ対応が国ごとに分岐

たとえるなら、海外旅行用の荷物です。国ごとに別のスーツケースを用意するより、「世界対応のACアダプタ＋国ごとの変換プラグだけ」にしたほうが圧倒的に楽です。ロボットでも同じで、大部分を共通にして、国ごとに違う部分をできるだけ小さく・後から差し替えられる形にまとめるのが基本方針になります。

ただし、何でも共通にすればよいわけではありません。全部の国に対応する「全部入り」の部品は高価で、消費電力やサイズでも不利なことがあります。共通化の度合いは、台数・国数・部品の単価差・認証費のバランスで決まる——これがこの章のテーマです。

私たちのロボットの場合

まだ量産プラットフォームがなく、試作から設計する段階です。これは実はチャンスで、最初の基板設計の時点で「差し替えられる余地」を仕込んでおけるからです。後から国を追加するときに基板を作り直さずに済むよう、この章の考え方を試作の段階から取り入れましょう。

2. ロボットのどこが共通化できるか

ロボットを構成要素ごとに分けて、「共通化しやすさ」で色分けしたのが下の図です。緑は世界共通にしやすい部分、橙は選び方しだいで共通化できる部分、赤は国ごとに変わりがちな部分です。

3. 通信部の4つの戦略

通信部分（LTEモジュール・アンテナ・SIM）をどう作るかで、SKUの数も認証の回数も大きく変わります。代表的な4つの戦略を比べます。

全バンド対応に近いグローバル版モジュール1種類で全輸出先をまかなう方法です。基板もソフトも在庫も1種類。アジアの主要国は、EG25-G や SIM7600G-H、LARA-R6001 のようなグローバル版で多くがカバーできます（チェッカーで確認できます）。

👍 長所

  • SKU・在庫・検証が最小
  • 国を後から追加しやすい
  • 生産・保守がシンプル

👎 短所

  • モジュール単価が高め
  • 対応バンドが多いほど、アンテナ設計・試験の範囲が広い
  • 中国など、グローバル版の認証が無い国は結局別SKU

基板は1種類で、同じフットプリントに載る地域版モジュールを仕向け地ごとに実装する方法です。例えば Quectel の EC25 シリーズは、日本版 EC25-J、EMEA/APAC向け EC25-EUX、豪州・中南米・アジア向け EC25-AU などの地域版があり、同じ29.0×32.0mmのLCCパッケージでグローバル版 EG25-G や Cat-1 の EC21/EG21-G とも互換とされています。

👍 長所

  • モジュール単価を抑えられる
  • 基板・筐体・ソフトは共通
  • 中国版も同じ基板に載せられる場合がある

👎 短所

  • モジュールの種類だけSKUと在庫が増える
  • 認証・キャリア認証は地域版の型番ごと
  • 地域版ごとの細かな差（電流、GNSS、ダイバーシティの有無など）の検証が必要

通信部分だけを M.2カードやMini PCIeカード、自社設計の通信サブ基板にして、本体とはコネクタでつなぐ方法です。本体は完全に共通のまま、組立の最終工程や現地でカードを差し替えられます。M.2版のモジュール（例: 5GのRM520N-GL）やMini PCIe版（EG25-G Mini PCIe など）が市販されています。

👍 長所

  • 本体は1SKU、カードだけ国別
  • 世代交代（LTE→5G RedCapなど）も差し替えで対応しやすい
  • 試作段階で複数モジュールを比較しやすい

👎 短所

  • コネクタ・カードの分だけ部材費とスペースが増える
  • 振動の多いロボットではコネクタの固定・信頼性に注意
  • アンテナ同軸ケーブルの取り回しが必要

ロボット本体にはLTEを入れず、各国で認証・キャリア承認を取得済みの市販LTEルーター（ゲートウェイ）をセットで提供する方法です。本体の無線はWi-Fi等だけになり、LTE関連の認証を大幅に減らせます。

👍 長所

  • LTEの認証・キャリア認証をルーターに任せられる
  • 市場投入が最速。少量・実証実験向き
  • 本体は完全に1SKU

👎 短所

  • ルーター代が1台ごとにかかる
  • 電源・設置・盗難など運用の手間が増える
  • 移動するロボットでは使いにくい。遠隔管理（死活監視・FOTA）の一体感が弱い
評価軸A グローバル1SKUB 地域版＋共通基板C カード差し替えD 外付けGW
モジュール等の単価高め安い中（カード・コネクタ分増）高い（ルーター1台分）
BOMの種類1地域版の数本体1＋カード数本体1＋市販品

私たちのロボットの場合

現実的な進め方は「試作はC（カード）で複数モジュールを比べる → 量産はAかB」です。試作時にM.2やMini PCIeで候補を差し替えて通信品質や消費電力を比べ、量産では基板にモジュールを直接実装してコストと振動耐性を確保します。最初の実証実験だけD（外付けルーター）で始めるのもよい選択です。

4. ピン互換ファミリーで基板を共用する

戦略Bの肝はフットプリントの共用です。モジュールメーカーは、同じ外形・同じピン配置で複数の地域版やカテゴリ違いを用意していることが多く、これを「ピン互換（pin-to-pin compatible）」と呼びます。代表例をまとめます（メーカーの公表内容に基づく。実際の互換範囲は各 Hardware Design 資料で確認してください）。

  • インターフェース：USB・UART・PCM・GNSSなど、モデルによって一部ピンが無効・予約（Reserved）になっている
  • アンテナ端子：ダイバーシティ（受信用の2本目）の有無、GNSSアンテナの有無
  • ソフト：ATコマンドやドライバの差、ファームウェア更新（FOTA）の方式
  • 認証：ピン互換でも認証は型番ごと。地域版ごとに最終製品の扱いを確認（第6節）

5. アンテナの広帯域化 ——「いちばん低いバンド」が大きさを決める

LTEのアンテナは、使う電波の波長に合わせた長さが必要です。基本形であるモノポールアンテナは、波長の約1/4（λ/4）の長さで共振します。波長は「光の速さ÷周波数」なので、周波数が低いほどアンテナは長くなります。つまり、対応バンドのうち最も低い周波数のバンドがアンテナの大きさを決めます。

市販の「LTE広帯域アンテナ」の多くは、698–960MHz（ローバンド）と 1710–2690MHz（ミッド・ハイバンド）の2つの帯域をカバーしています。アジアの主要バンドに当てはめると次のとおりです。

  • ローバンド 698–960MHz：B28（700）、B20（800）、B18/B19/B26（日本の800）、B5（850）、B8（900）
  • ミッド・ハイバンド 1710–2690MHz：B3（1800）、B39（1900 TDD）、B1（2100）、B34（2000 TDD）、B40（2300 TDD）、B41（2500 TDD）、B7/B38（2600）
  • 範囲外：日本の B11/B21（1.5GHz帯、1427.9–1510.9MHz）、B42（3.5GHz帯）、米国の B71（600MHz帯）

日本の1.5GHz帯（B11/B21）は容量用の補助バンドで、B1/B3/B19などが使えれば通信はできます。ただし、日本向けに最高の性能を狙うなら 1.4–1.5GHz まで対応したアンテナを選ぶ価値があります。

もう一つ重要なのが グラウンド（GND）面です。小型のチップアンテナやフレキシブル基板アンテナでも、ローバンドでは基板や金属シャーシのGNDが「アンテナの片割れ」として働きます。GND長が波長に比べて短すぎると、ローバンドの効率がガクッと落ちます。ロボットの場合、筐体の金属部分やモーター・ケーブルとの位置関係も効率に影響するので、筐体の試作ができた段階で実機のアンテナ効率（OTA測定）を確認します。

MIMOと2本目のアンテナ

Cat-4 などは受信用に2本のアンテナ（メイン＋ダイバーシティ）を前提としており、キャリアの試験でも2本での性能を求められることがあります。Cat-1bis や LTE-M は1本で動くため、アンテナの置き場が限られるロボットでは有利です。カテゴリの選び方は 5章 を参照してください。

6. 認証をどこまで使い回せるか

「モジュールが認証済みなら製品はそのまま売れる」と思われがちですが、実際はモジュールの認証を土台に、最終製品として何が追加で必要かを国ごとに判断します。共通化の観点で押さえておきたいのは次の3点です。

項目使い回しやすいもの取り直し・追加が必要になりやすいもの
無線の認証（技適・FCC・NCC・KCなど）モジュール単体の認証（モジュラー認証）。指定のアンテナ種別・利得の範囲内で使えば、最終製品の試験を大きく減らせる制度が多いアンテナ利得の超過、他の無線（Wi-Fi等）との同時送信、表示が外から見えない場合の製品側表示。米国では FCC KDB 996369 がモジュール組込みの指針
モジュールの型番変更同じ型番内のファーム更新（多くは届出不要だが要確認）ピン互換の別型番（地域版⇔グローバル版）は別の認証。製品側の申請・宣言書・ラベルも更新
キャリア認証モジュールが事前認証済みなら、最終製品の試験項目が減ることがある最終製品（型番）単位の承認。アンテナや筐体を変えると再試験の可能性
EMC・安全（電気安全・電磁両立性）同一設計なら各国で試験報告書を流用しやすい（国際規格ベースのCBスキームなど）国別の差分規格、現地試験所での試験を求める国

つまり「同じファミリーなら認証も同じ」ではありません。戦略Bで地域版を増やすと、そのたびに認証の手続きが（全部ではないにせよ）発生します。一方、戦略Aでも国ごとの手続きは必要ですが、型番が1つなので書類・試験データを使い回しやすいのが利点です。詳しい制度は 9章、各国の要点は 10章 で扱います。

7. eSIMで「回線」を共通化する

ハードウェアを共通化しても、SIMカードを国ごとに差し替えていては工場や現地の作業が残ります。そこで有効なのが eSIM（embedded SIM）です。正確には、書き換え可能なSIMチップを eUICC と呼び、中に入れる事業者の契約情報をプロファイルと呼びます。

  • ハードは1種類：基板にチップ型SIM（MFF2など）を実装。振動・抜き差しに強く、ロボット向き
  • プロファイルを後から入れる：出荷先が決まってから、遠隔で現地事業者（またはグローバルIoT事業者）のプロファイルを書き込む
  • IoT向けの標準：GSMA は M2M 向けの SGP.02 に加え、IoT向けの新しい仕様 SGP.32（v1.0 は2023年公開）を定めており、画面のない機器でもプロファイルを管理しやすくなっています
eSIMでも解決しないこと

eSIMは「SIMの中身」を共通化する技術で、バンドの違いや電波認証は解決しません。また、グローバルSIM（海外事業者の回線）でずっとローミング接続する「恒久ローミング」を制限・禁止する国や事業者があります。長期運用する国では現地事業者のプロファイルに切り替える計画を立てておきます。SIMの種類と回線の選び方は 7章 で扱います。

8. ファームウェアは「1ビルド＋国別設定」

9. どの戦略が得か：概算コストを比べる

最後に、4つの戦略をお金で比べてみます。下の数値は説明用の仮の値です。自社の見積もりに置き換えて、どの条件で結論が変わるかを体感してください。

このモデルからわかる傾向は次のとおりです。

  • 台数が少ないうちは A（グローバル1SKU）や D（外付け）が有利。SKU管理や認証の固定費が支配的だからです。
  • 台数が増えると B（地域版）が逆転。1台あたりの単価差が積み上がり、SKUが増える固定費を上回ります。逆転する台数（損益分岐点）は「増えるSKUの固定費 ÷ 単価差」で概算できます。
  • C（カード）は1台あたりのカード費がかかるものの、本体を完全共通にできる安心感と、将来の世代交代への備えが価値になります。
  • 現実には、ここに入っていない要素——開発期間、アンテナ設計の難しさ、キャリア認証の期間、部品の供給寿命（EOL）——も効いてきます。数字は判断の「たたき台」として使いましょう。

国の組み合わせを変えたり、中国を加えたりすると結果が大きく変わります。ぜひ バンド共通化チェッカー で試してください。

11. 私たちのロボットの進め方

ここまでの内容を、試作段階から使えるチェックリストにまとめます。

  • 最初の輸出先（2〜3か国）と、将来追加する可能性がある国をリストにした
  • 各国で組む事業者（または回線サービス）の候補を決めた
  • バンド共通化チェッカーで、グローバル版と地域版の候補を洗い出した
  • 中国を対象にするか決め、対象なら別SKUとして計画した
  • 試作基板は、候補モジュールを差し替えられる形（M.2／ピン互換フットプリント）にした
  • アンテナの帯域（最低周波数）を決め、筐体にアンテナ用スペースと樹脂窓を確保した
  • SIMは eSIM（チップ型）を実装できるようにした
  • ファームウェアは1ビルド＋国別設定（APN・バンド・事業者設定）の構成にした
  • 認証ラベル・説明書・ACアダプタだけを国別にできるよう、梱包・ラベル工程を設計した
  • 台数見込みで戦略A〜Dの概算コストを比較し、量産時の方針を決めた

まとめ

  • SKUが1つ増えると、設計検証・認証・在庫・生産・保守がまるごと増える。大部分を共通にし、国別の部分を小さく・差し替えやすくするのが基本。
  • 筐体・SoC・ソフト・基板の大部分は共通化しやすい。LTEモジュール・アンテナ・SIM・通信設定は選び方しだい。ラベル・説明書・ACアダプタ・キャリア認証・中国向けは国別になりがち。
  • 通信部の戦略は A グローバル1SKU／B 地域版＋共通基板／C カード差し替え／D 外付けゲートウェイ。台数が増えるほど B が有利になりやすい。
  • ピン互換ファミリーなら基板は共通にできるが、認証は型番ごと。電源・ピン・アンテナ端子の差も要確認。
  • アンテナは 698–960MHz / 1710–2690MHz の広帯域品でアジアの主要バンドをほぼカバー。最も低いバンドがアンテナの大きさを決める。
  • eSIMで回線を、1ビルド＋国別設定でファームウェアを共通化する。

用語

SKU
Stock Keeping Unit。在庫・生産を管理する最小単位。中身が1つでも違えば別SKU。
BOM
Bill of Materials。部品表。どの部品を何個使うかの一覧。
フットプリント
基板上で部品を載せるための銅パターン（パッド配置）。
ピン互換
外形とピン配置が同じで、同じフットプリントに載せ替えられること。機能や電気的特性まで同じとは限らない。
グローバル版／地域版
多くの国のバンドに対応したモジュールと、特定地域のバンドに絞った安価なモジュール。
M.2 / Mini PCIe
カード型モジュールの規格。コネクタで基板に差し込む。
λ/4（4分の1波長）
モノポールアンテナが共振する基本の長さ。λ(mm) ≒ 300,000 ÷ 周波数(MHz)。
OTA測定
Over The Air。実機を電波暗室に置き、アンテナ込みの送受信性能（TRP/TIS）を測る試験。
MFBI
Multiple Frequency Band Indicator。1つの周波数を複数のバンド番号で報知し、上位集合バンド（例: B26）の端末も接続できるようにする仕組み。
モジュラー認証
無線モジュール単体で取得する認証。条件を守れば最終製品の試験・申請を簡略化できる。
eUICC / プロファイル
書き換え可能なSIMチップ（eSIM）と、その中に入れる事業者の契約情報。
SGP.32
GSMA の IoT 向け eSIM 仕様。画面のない機器でもプロファイルを遠隔管理しやすくする。
APN
Access Point Name。データ通信の接続先を示す名前。事業者・契約で異なる。
バンドロック
モジュールが使うバンドを設定で限定すること。
MBN
Quectel などのモジュールが持つ、事業者ごとの設定ファイル。SIMに応じて自動選択できる。
MCC / MNC
Mobile Country Code / Mobile Network Code。IMSIの先頭にある国番号と事業者番号（日本のMCCは440/441）。
