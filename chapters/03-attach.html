CHAPTER 03

接続の流れ（アタッチ）

ロボットの電源を入れてから、最初の1パケットが送れるようになるまでの数秒〜数十秒のあいだに、端末・基地局・コア網のあいだでは何十ものやり取りが行われています。その流れを1ステップずつ再生しながら理解し、「つながらない」ときにどこを疑えばよいか判断できるようになりましょう。

この章のゴール

  • 電源ON → セルサーチ → RRC接続 → Attach → 認証 → IP割当 の順番と、それぞれの目的を説明できる
  • SIMとHSSが秘密鍵Kで「答え合わせ」する認証（AKA）の考え方がわかる
  • RRC Idle / Connected の違いと、省電力機能（DRX・eDRX・PSM）の得失がわかる
  • AT+CEREG? の結果から登録状態を読み取り、「つながらない」原因の当たりをつけられる

1. 全体像 — 「ホテルのチェックイン」にたとえると

第2章で、LTEのネットワークが UE（User Equipment：端末）、eNodeB（eNB：基地局）、そしてコア網 EPC（Evolved Packet Core） の中の MME（制御の司令塔）、HSS（加入者データベース）、S-GW / P-GW（データの出入口）で構成されることを見ました。この章では、それらの登場人物が「電源ON」の瞬間からどう連携するのかを追いかけます。

流れ全体を、初めて泊まるホテルでのチェックインにたとえると覚えやすくなります。

LTEの手順ホテルでたとえると主な相手層
PLMN選択予約してあるホテル（系列）を決めるUE内部（SIMの情報）—
セルサーチ（PSS/SSS）ホテルの看板と入口を見つけるeNB物理層
システム情報（MIB/SIB）入口の館内案内を読む（受付はどこか、何階か）eNBRRC（報知）
ランダムアクセス（RACH）フロントで「すみません」と手を挙げるeNBMAC
RRC接続担当スタッフが付いて、専用の窓口ができるeNBRRC
Attach要求・認証（AKA）予約名を告げ、本人確認（身分証の照合）MME・HSSNAS
セキュリティ確立以後の会話は小声（暗号）で、と取り決めるMME・eNBNAS / AS
デフォルトベアラ・IP割当部屋の鍵とWi-Fiパスワードを受け取るS-GW・P-GWNAS / GTP

表の「層」の欄に出てくる NAS（Non-Access Stratum） は「端末とコア網（MME）のあいだの会話」、AS（Access Stratum） は「端末と基地局のあいだの会話」を指します。NASのメッセージは基地局を通りますが、基地局は中身を解釈せずにそのままMMEへ中継します。手紙を郵便局（基地局）に預けても、郵便局は封を開けずに宛先（MME）へ届けるのと同じです。

そして RRC（Radio Resource Control） はAS側の制御プロトコルで、「この端末にどの無線リソースを割り当てるか」を端末と基地局で取り決めます。ここを押さえておくと、次のシーケンス図がぐっと読みやすくなります。

2. シーケンス図で1ステップずつ再生する

下の図は、3GPP（LTEを標準化している国際団体）の仕様 TS 23.401 に書かれている「初期アタッチ」手順を、学習用に要点だけ残して簡略化したものです。縦の点線がそれぞれの装置、横の矢印がメッセージです。「次へ」を押すと該当する矢印が強調され、そのステップで関わる装置の枠が太くなります。

ロボットでは：起動シーケンスをLTE待ちにしない

アタッチは電波が良ければ1〜数秒で終わりますが、初回起動・輸出先での初回電源ON・圏外からの復帰では、対応する全バンドを探すセルサーチに数十秒〜数分かかることがあります。ロボットのソフトは「LTEがつながるまで起動を止める」のではなく、LTEは並行して接続を試み、つながったら状態を通知する非同期の設計にしましょう。また、輸出先ごとに使うバンドをモジュール設定で絞り込むと、探す時間が短くなります（第4章・第8章）。

3. 各ステップをもう少し詳しく

3-1. PLMN選択：どの事業者につなぐか

SIMの中には、自社網のID（HPLMN）、同等に扱う網のリスト（EHPLMN）、ローミング時の優先リスト（OPLMN）、そして「以前拒否されたので当面避ける網」＝禁止PLMNリスト（FPLMN）が入っています。端末は基本的にこの情報に従い、自動で網を選びます（自動選択モード）。モジュールでは AT+COPS コマンドで手動選択に切り替えることもできます。

日本国内の自社SIMならHPLMNを探すだけですが、輸出先で日本のSIMやグローバルSIMを使う場合はローミングになり、「どの現地事業者に、どの順でつなぐか」がSIM側のリストと契約で決まります。一度拒否された網はFPLMNに登録されて以降しばらく試されなくなるため、現地試験で「最初に失敗したら、その後もつながらない」という現象の原因になることがあります。

3-2. セルサーチとシステム情報：看板と館内案内

基地局は、端末がいてもいなくても同期信号と報知情報を送り続けています。PSSは3種類、SSSは168種類あり、その組み合わせで 3 × 168 = 504 通りの物理セルIDが表せます。端末は周波数を一つずつ聞いて同期信号を探し、見つかったらRSRP（Reference Signal Received Power：基準信号の受信電力）などで電波の強さを測ります。

MIBは約40ミリ秒ごとに繰り返し送られ、帯域幅とフレーム番号がわかります。SIB1にはPLMN ID、TAC（トラッキングエリアコード＝呼び出しの単位となるエリア番号）、セル単位の利用制限（cell barred）などが入り、端末は「このセルで待受してよいか」をここで判断します。

「対応バンド」はここで効いてくる

端末は自分が対応するバンドの周波数しか聞きにいけません。現地の事業者がBand 3とBand 8で運用していても、モジュールがBand 1とBand 19にしか対応していなければ、セルサーチは永遠に何も見つけられません。これが輸出で最も多い「つながらない」原因のひとつです（詳しくは第4章、バンド共通化チェッカー）。

3-3. ランダムアクセス（RACH）：4ステップの挨拶

RACH（Random Access Channel）の手順は、通常4つのメッセージで構成されます。Msg1（プリアンブル送信）、Msg2（ランダムアクセス応答：タイミングアドバンスと送信許可）、Msg3（RRC接続要求：端末の識別子入り）、Msg4（RRC接続セットアップ：衝突解消）です。複数の端末が偶然同じプリアンブルを選んでしまっても、Msg4で自分の識別子が返ってきた端末だけが「自分が選ばれた」と判断します。

タイミングアドバンスとは「基地局から遠い端末ほど、少し早めに送信してね」という補正値です。電波は光速で進みますが、数kmあれば数マイクロ秒の遅れになり、多数の端末の信号を基地局で揃えて受信するためにはこの補正が欠かせません。

3-4. 認証（AKA）：秘密鍵Kは電波に乗らない

LTEの認証方式 EPS-AKA（Authentication and Key Agreement） の要は、SIMとHSSだけが同じ秘密鍵Kを持っていることです。Kは製造時にSIMへ書き込まれ、外から読み出すことはできません。認証では、Kそのものではなく「Kを使って計算した答え」だけを見せ合います。

この仕組みのおかげで、電波を盗聴されても K は漏れません。また RAND は毎回変わるので、過去の答えを録音して再生する「なりすまし」も通用しません。さらに AUTN には網側しか作れない検証値と通し番号（SQN）が入っており、SIMはそれを確かめることで偽の基地局にだまされるのを防ぎます。

認証が通ると、SIMとHSS（MME）の両方で、Kから派生させた同じ鍵 KASME ができます。以後の暗号化・改ざん防止の鍵はすべてこのKASMEから作られます。

3-5. セキュリティ確立：NASとASの2段階

鍵ができても、どのアルゴリズムで暗号化するかを決めなければ使えません。まずMMEと端末の間で NASセキュリティモード（NAS SMC）を実行し、続いて基地局と端末の間で ASセキュリティモード（AS SMC）を実行します。LTEの標準アルゴリズムには、SNOW 3Gベース（EEA1/EIA1）、AESベース（EEA2/EIA2）、ZUCベース（EEA3/EIA3）の3系統があり、ZUCは中国で開発された方式です。

暗号化（盗聴防止）と完全性保護（改ざん防止）は別物で、制御メッセージには必ず完全性保護がかかります。セキュリティ確立の前に送られるAttach要求などは暗号化されていないため、初回はIMSIが平文で流れる弱点があり、LTEでは2回目以降に一時ID（GUTI）を使うことでその機会を減らしています。

3-6. デフォルトベアラとIP割当：Attach＝即データ可能

ベアラ（bearer）とは「決まった品質で端末〜P-GW間を運ぶ論理的な通路」のことです。LTEではAttach手順の中で必ず1本、デフォルトベアラが作られ、P-GWが APN（Access Point Name） に応じたIPアドレスを割り当てます。APNは「どの出口ネットワークにつなぐか」を示す名前で、たとえばインターネット向けと、閉域網（企業網）向けで別のAPNが用意されていることがあります（第2章参照）。

3Gまでは「網に登録（Attach）」と「データ通信の開始（PDPコンテキスト有効化）」が別手順でしたが、LTEでは両方がまとめて行われます。そのため、APNの設定が間違っているとAttachそのものが拒否されることがあります。この点は後のトラブルシュートで重要になります。

もっと詳しく：APNはいつ送られる？ IPv4とIPv6は？

APNはAttach要求に同梱できますが、APNは暗号化前に送らない方が望ましいため、端末が「ESM情報は後で送る」フラグを立て、セキュリティ確立後に ESM Information として送る方式もよく使われます。端末がAPNを指定しなければ、HSSに登録された契約上のデフォルトAPNが使われます。

PDNタイプとして IPv4 / IPv6 / IPv4v6（デュアルスタック）を要求でき、事業者によってはIPv6のみを割り当ててIPv4はNAT64で変換する場合もあります。サーバー側がIPv4しか持たない構成では注意が必要です。

4. RRC Idle と RRC Connected — 「待受」と「通話中」

アタッチが終わった端末は、ずっと基地局と専用接続を保っているわけではありません。しばらく通信がないと、基地局は無線リソースを解放して端末を RRC Idle（待受） 状態に戻します。この無通信タイマーの長さは事業者の設定次第で、数秒〜数十秒程度が一般的です。

大事なのは、RRC Idleでもコア網への登録・IPアドレス・デフォルトベアラは残っていることです。専用窓口は閉じたけれど、ホテルの部屋（IPアドレス）はそのまま、という状態です。再び送信したいときは、RACHからRRC接続を張り直して Service Request を送るだけで、数十〜百数十ミリ秒程度で通信を再開できます。網側からデータが届いた場合は、端末が属するトラッキングエリア全体に ページング（呼び出し） が送られ、端末がそれに応えて接続します。

ロボットでは：キープアライブと状態遷移のバランス

遠隔監視のためにMQTTなどでサーバーへ常時接続する場合、キープアライブ（生存確認）の送信のたびに Idle → Connected の遷移が起きます。周期が短すぎるとほぼ常時Connectedになり電力を消費し、長すぎると事業者のCGNAT（第2章）がセッションを忘れて、サーバーからの指令が届かなくなります。一般には数十秒〜数分の範囲で、実回線で試験して決めます。

5. 省電力の仕組み：DRX・eDRX・PSM

Idle中の端末は、ずっと受信機を動かしているわけではありません。DRX（Discontinuous Reception：間欠受信）により、決まった周期（通常0.32〜2.56秒、典型的には1.28秒）ごとに一瞬だけ目を覚まし、自分宛ての呼び出しがあるかを確認します。IoT向けにはこれをさらに伸ばした eDRX（extended DRX） と、呼び出し確認すら止めて眠る PSM（Power Saving Mode） が用意されています。

どれも「どれだけ眠るか」と「網から呼ばれてどれだけ早く反応できるか」のトレードオフです。下のウィジェットでモードと周期を変えると、1時間のあいだに受信機が何回起きるか（縦線）と、呼び出しへの最大待ち時間がどう変わるかを確認できます。

機能何をするか設定できる周期の例網からの到達性主な用途
DRX（Idle）周期的に起きてページングを確認0.32〜2.56秒ほぼ即時スマホ、常時待受の機器
eDRX起きる間隔を大幅に延長LTE（LTE-M含む）で最大約43.7分、NB-IoTで最大約2.9時間周期分遅れるメーター、トラッカー
PSMアクティブタイマー（T3324）後は受信も停止定期TAU（T3412延長値）は最大約413日次に起きるまで不可1日数回の送信だけの電池機器

eDRXとPSMは、端末が「この値でお願いします」と要求し（モジュールでは AT+CEDRXS、AT+CPSMS）、網が最終的な値を決めて返す方式です。要求しても網が対応していなければ使えません。LTE-MやNB-IoTでは広く使われますが、Cat-1/Cat-4の通常のLTE網ではeDRX/PSMを提供していない事業者もあるため、輸出先の事業者ごとに確認が必要です（カテゴリの違いは第5章）。

ロボットでは：PSMが役立つ場面・困る場面

稼働中のロボットはモーターやコンピュータがLTEの何百倍も電力を使うので、LTEの省電力はあまり効きません。むしろ「遠隔から今すぐ停止・呼び出し」ができないPSMは稼働中は使うべきではありません。一方、輸送中・倉庫保管中・電源OFF時の位置トラッキングを小さな補助バッテリーで続けたい、といった用途ではPSM/eDRXが大きな武器になります。「稼働モード」と「保管モード」で設定を切り替える設計も考えられます。

6. 登録状態を確認する：AT+CEREG?

LTEモジュールは、ホストCPUから ATコマンド（モデムに文字で命令を送る古典的な方式）で制御します。アタッチがうまくいったかを確かめる最も基本的なコマンドが、EPS（LTEのパケット網）への登録状態を返す AT+CEREG? です。

AT+CEREG=2
OK
# 位置情報（TAC・セルID）付きで状態を報告するよう設定
AT+CEREG?
+CEREG: 2,1,"1A2B","01C3D405",7
OK
# n=2（報告モード）, stat=1（ホーム網に登録済み）, TAC=1A2B, セルID=01C3D405, AcT=7（E-UTRAN＝LTE）

応答の形式は +CEREG: <n>,<stat>[,<tac>,<ci>,<AcT>…] です。最初の n は「状態変化を自動で通知するか」の設定値で、2番目の stat が登録状態です（値は例示です）。

stat意味読み方・よくある原因
0未登録・検索もしていない無線OFF（AT+CFUN=0/4）、SIM未挿入、手動で登録を止めている
1登録済み（ホーム網）正常。自社SIMで自社網につながっている
2未登録・検索中／登録試行中起動直後なら待つ。ずっと続くなら電波・アンテナ・バンド非対応を疑う
3登録拒否網は見つかったが断られた。SIM未開通・契約・ローミング不可・APNを疑う
4不明LTEの圏外など、状態が判定できない
5登録済み（ローミング）正常。グローバルSIMや海外での日本SIMではこれが正常値

このほか、緊急通報のみ可能な状態（8）なども定義されています。末尾の AcT（アクセス技術）は 7 がLTE（E-UTRAN）、9 がNB-IoTです。AT+CEREG=3 にすると、拒否されたときの理由コード（reject cause）も返すモジュールがあり、原因の切り分けに役立ちます。電波の強さを見る AT+CESQ、SIMの状態を見る AT+CPIN? などと組み合わせた実践的な使い方は第8章で扱います。

「登録できた＝通信できる」とは限らない

stat が 1 か 5 でも、APNの設定ミスやファイアウォールで実際のデータが通らないことがあります。アプリ側では、最終的にサーバーとの疎通（例：MQTT接続の成功）で判定しましょう。

7. 「つながらない」ときのトラブルシュート

現地で「LTEがつながらない」と言われたとき、闇雲に設定を変える前に、アタッチ手順のどこで止まっているかを考えると原因が絞れます。基本的には下から順に、「電波が届いているか → セルが見えるか → 加入者として受け入れられるか → IPが得られるか → 目的のサーバーに届くか」と積み上げて確認します。

現地や工場で初めて通信を試すときは、次のチェックリストを上から確認していくと、原因の切り分けがスムーズです。チェック状態はこのブラウザに保存されます。

  • アンテナ（主・ダイバーシティ）が正しいコネクタに確実に接続されている
  • AT+CPIN? が READY を返す（SIMが読めている）
  • 回線管理画面で、SIMが「開通済み」かつデータ通信可能なプランである
  • 現地事業者のバンドにモジュールが対応し、バンド設定で除外していない
  • 海外なら、その国・事業者・方式（LTE/LTE-M/NB-IoT）でローミングが許可されている
  • APN・認証方式・PDNタイプが事業者の指定どおり設定されている
  • AT+CEREG? の stat が 1 または 5 になる
  • IPアドレスが割り当てられ、DNS解決とサーバーへの接続ができる
  • 状態（CEREG・拒否理由・RSRP等）がロボットのログに記録されている
ロボットでは：現地サポートのために“ログに残す”

輸出したロボットが現地でつながらないとき、開発者がその場にいるとは限りません。AT+CEREG の stat と拒否理由、接続中の PLMN（MCC/MNC）、RSRP/RSRQ、SIMのICCID、モジュールのファームウェア版数を定期的にログに残し、後から取り出せるようにしておくと、上の①〜⑦のどこで止まったかを遠隔で判断できます。

まとめ

  • 電源ONからの流れは PLMN選択 → セルサーチ（PSS/SSS）→ MIB/SIB → RACH → RRC接続 → Attach要求 → 認証（AKA）→ セキュリティ確立 → デフォルトベアラ・IP割当。
  • 前半（〜RRC接続）は端末と基地局の「無線の手続き」、後半（Attach以降）は端末とコア網の「加入者の手続き（NAS）」。
  • 認証では SIM と HSS が同じ秘密鍵 K で同じ問題を解き、答えを照合する。K 自体は電波に乗らない。
  • LTEではAttachの中でIPアドレスまで割り当てられる（常時接続）。そのためAPNの誤りが登録失敗として現れることがある。
  • 無通信になると RRC Idle に戻るが、登録とIPは残る。DRX・eDRX・PSMは「省電力」と「網からの到達性」のトレードオフ。
  • AT+CEREG? の stat：1・5 は登録済み、2 は検索中、3 は拒否。2が続けば電波・バンド、3なら SIM・契約・ローミング・APN を疑う。

Public Land Mobile Network。事業者の携帯網。MCC（国番号）＋MNC（事業者番号）で識別する。
PSS / SSS
Primary / Secondary Synchronization Signal。基地局が常時送る同期信号。組み合わせで物理セルID（PCI）がわかる。
MIB / SIB
Master / System Information Block。セルの報知情報。帯域幅、PLMN、TAC、アクセス方法などが入る。
RACH
Random Access Channel。端末が最初に基地局へ合図を送るための手順・チャネル。
RRC
Radio Resource Control。端末と基地局の間の無線制御プロトコル。Idle / Connected の状態を持つ。
NAS / AS
Non-Access Stratum（端末〜コア網の会話）／Access Stratum（端末〜基地局の会話）。
Attach
端末がコア網に自分を登録する手順。LTEではデフォルトベアラ確立とIP割当も含む。
IMSI / GUTI
IMSI は SIM 固有の加入者識別番号。GUTI は網が割り当てる一時ID で、IMSI の露出を減らす。
AKA
Authentication and Key Agreement。SIM と HSS が共有する秘密鍵 K を使った相互認証・鍵合意の方式。
SMC
Security Mode Command。使う暗号・完全性保護アルゴリズムを決めて保護を開始する手順（NAS と AS の2段階）。
ベアラ
一定の品質で端末〜P-GW間のデータを運ぶ論理的な通路。Attach時に作られるものをデフォルトベアラと呼ぶ。
APN
Access Point Name。どの出口ネットワーク（インターネット、閉域網など）につなぐかを示す名前。
TAU
Tracking Area Update。Idle中の端末が、トラッキングエリアの移動時や定期的に位置を網へ知らせる手順。
DRX / eDRX
(extended) Discontinuous Reception。周期的に起きて呼び出しを確認する間欠受信。eDRXは周期を大幅に延長したもの。
PSM
Power Saving Mode。登録を保ったまま、受信も止めて深く眠るモード。T3324・T3412 タイマーで制御。
CEREG
EPS（LTEパケット網）への登録状態を問い合わせ・通知する標準ATコマンド（3GPP TS 27.007）。
